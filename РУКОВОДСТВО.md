# Руководство по шаблону сайта-визитки

Как быстро и без ошибок собрать новый сайт из этого шаблона.

> **Прочитать целиком до первой правки.** Шаблон — не статичная вёрстка, а
> Webflow-экспорт с самописным движком анимаций. Половина «странных» багов
> возникает из-за правок, которые в обычной вёрстке безопасны.

Все кастомные CSS-правки живут в одном `<style>`-блоке внутри `<body>`
(`ADVOKAT CUSTOM`) — внешний CSS не трогаем никогда, чтобы шаблон
оставался переиспользуемым. Блок сейчас ЕДИНЫЙ, но повторён (с
одинаковым содержимым) в каждом из трёх HTML-файлов — так же, как раньше
`index.html`/`page.html` держали байт-в-байт одинаковыми: любую правку
в `<style>`, в `<!-- TWEAK-PALETTE -->` или в общих секциях
(шапка/навигация, "Преимущества", CTA, футер) нужно вносить во ВСЕ ТРИ
файла (`index.html`, `mama.html`, `papa.html`) синхронно — они разошлись
только в контенте hero/карточек-ситуаций/FAQ/meta-тегов, но не в CSS/JS
инфраструктуре. Смотрите 1.1.1.

### 1.2. Главное правило: движок пишет inline-стили

`f1-assets-script.js` при загрузке **измеряет** элементы
(`getBoundingClientRect`, `getComputedStyle`) и затем **записывает им
inline-стили** через GSAP: `width`, `height`, `transform`, `position`,
`top`, `left`, `opacity`.

> **CSS-правило с `!important` побеждает inline-стиль.** GSAP пишет
> `element.style.width = '131px'` без `!important`. Значит правило
> `.nav-button{width:auto !important}` **запрещает движку менять ширину** —
> анимация ломается молча, без ошибок в консоли.

**Запрещено** трогать `width` / `height` / `display` / `overflow` /
`transform` (и особенно с `!important`) у элементов из таблицы 1.4.

**Разрешено** менять у них: `color`, `background-color`, `font-size`,
`letter-spacing`, `margin`, `padding`, `border-radius`. Этих свойств движок
не касается — в коде есть явные `delete fromVars.fontSize` и `delete
fromVars.color`.

### 1.4. Система «призраков» (GhostEngine)

Элемент в шапке плавно «перелетает» на своё место в hero при скролле.
Элементы ходят **парами**:

| «Реальный» (в шапке) | «Призрак» (в hero, невидим) | Тип анимации |
|---|---|---|
| `.nav-logo-item .nesh-logo` | `.nesh-logo-ghost` | logo |
| `.nav-button` | `.hero-cta-button` | logo |
| `.nav-button-secondary` | `.hero-button` | logo |
| `.hero-navigation-link[data-link-id]` | `.hero-link-ghost[data-link-id]` | link |
| `.nav-webflow-bg` | `.hero-card-2-bg` | background |
| `.nav-webflow-icon` | `.hero-webflow-icon` | icon_center |
| `.nav-webflow-text` | `.hero-webflow-projects-text` | text_font |
| `.nav-experience-bg` | `.experience-bg` | background |
| `.nav-experience-numb` | `.experience-number` | icon_center |
| `.nav-experience-text` | `.experience-text` | text_font |

Источник: `GhostEngine.createAll()`.

**Правила для пар:**

1. **Меняешь контент в одном — меняй и в парном.** Иначе на десктопе видно
   одно значение, а на мобильном другое.
2. **Не меняй тип тега.** Типы `icon_center` и `background` считают
   `scaleX = ширина_призрака / ширина_реального`. Если призрак был `<svg>`,
   а стал `<p>` — пропорции разъедутся, элемент растянет.
3. **Сохраняй `data-flip-*` и `data-tl-*`** — движок читает настройки с них.
4. **Ниже 768px GhostEngine выключен** (`if (window.innerWidth < 768) return`).
   Значит мобильные баги — это почти всегда чистый CSS, а не JS.

### 1.5. Система привязки карточек (MagneticPositions)

В секции «Преимущества» карточки физически лежат в конце DOM, а визуально
плавают внутри текста. Связь — через атрибуты:

```html
<!-- якорь внутри текста: резервирует место -->
<span data-connect="w" class="span" style="white-space:nowrap">&nbsp;&nbsp;&nbsp;</span>

<!-- карточка: цепляется к якорю -->
<div data-connect="w" data-connect-mobile="w-mobile"
     data-origin="center center" data-anchor-pos="center center"
     data-offset="0, 16%" class="capa-card">
```

| Атрибут | Что делает |
|---|---|
| `data-connect` | id связи с якорем (десктоп) |
| `data-connect-mobile` | то же для <768px (у мобильного текста свои якоря) |
| `data-origin` | какая точка карточки цепляется |
| `data-anchor-pos` | к какой точке якоря |
| `data-offset` | сдвиг `X, Y` (px / % / vw) — **безопасный способ подвинуть** |

**Важно:** якорь и карточка ищутся так — `[data-connect="id"]:not([data-origin])`
это якорь, с `data-origin` — карточка. Ширина якоря должна примерно
соответствовать ширине карточки.

### 1.6. Брейкпоинты и цвета

Брейкпоинты Webflow: **991 / 767 / 479**. Плюс `clamp()` для плавных размеров.

Изначально шаблон жёлтый (`--yellow:#ffff23`) на тёплом бежевом фоне
(`#d5cfbe`). У этого сайта (Олег Евсин) схема уже перекрашена в синюю —
ниже описано, где живёт цвет и как менять его **полностью**, без «пятен»
старого цвета. Это писалось после реальной перекраски проекта — каждый
пункт ниже хотя бы раз был причиной «забытого» места.

**Переменные (задаются в `body{}` в custom `<style>` блоке, а не в `:root`,
чтобы порядок в документе гарантированно побеждал все breakpoint-версии
`--yellow`/`--black` из внешнего Webflow CSS):**

```css
body {
  --yellow: #7BBBFF;   /* акцент: фон кнопок, иконки, точки, бордеры */
  --black: #050F2A;    /* "чернила": текст на var(--yellow), сам body{color} */
  color: #050F2A;      /* дублирует --black как обычное свойство —
                           нужно элементам, которые наследуют цвет от body
                           напрямую, а не через var(--black) */
  background-color: #F2FDFF;
}
```

**Из чего реально состоит "смена цвета" — 4 категории, все обязательны:**

1. **`var(--yellow)` / `var(--black)` в CSS** — их 22+ использований во
   внешнем Webflow CSS (иконки, точки, бордеры, фон+текст кнопок в парах
   вида `background:var(--yellow); color:var(--black)`). Правятся одним
   переопределением переменной выше.

2. **Хардкод-хекс во ВНЕШНЕМ Webflow CSS** (никогда не редактируется
   напрямую, см. 1.1) — минимум 7 селекторов: `.hero-button`,
   `.hero-cta-button`, `.cta-button` (фон), `.experience-number`,
   `.nav-experience-numb` (текст-цвет счётчика "N лет опыта" и его
   `nav`-пары), `.nav-logo` (**осторожно** — у него ДВЕ раздельные версии
   правила: бейдж `background:var(--yellow); color:var(--black)` и
   отдельная строчная версия `color:#ffff23` без фона; если добавить
   общий `color:` override на класс — он перекроет ОБЕ версии и на
   бейдже текст сольётся с его же фоном, см. живой пример такого бага
   ниже), `.popup-card-top-item` (градиент `linear-gradient(#цвет1,
   #цвет2)` для текста через `background-clip:text`).
   **Чинится** точечным `override` в custom `<style>` блоке — того же
   селектора с `var(--yellow)`/`var(--black)`, **не хардкод-хексом**
   (см. пункт про "забытые места" ниже — это ровно та ошибка, которую
   поймали и переделали).

3. **Хардкод-хекс в САМОМ custom `<style>` блоке** — это код, который
   писали мы сами в прошлые правки, и это самый частый источник "забытых
   пятен старого цвета" при следующей смене палитры. Известные на
   август 2026: `.service-toggle-btn` (фон+текст кнопки "Показать все
   услуги"), `.swiper-bullet.is-active` (точка активного слайда отзывов,
   **два** правила — десктоп и мобильный брейкпоинт), `.faq-toggle:hover
   .faq-icon` (фон `#EDECDA`, тёплый бежевый — leftover от жёлтой эры,
   не критично, но и не синий).
   **Перед следующей сменой палитры** — обязательно:
   ```bash
   node -e "
   const fs=require('fs'); const h=fs.readFileSync('index.html','utf8');
   const s=h.indexOf('/* ===='), e=h.indexOf('</style>', s);
   const re=/color:\s*#[0-9a-fA-F]{3,6}\s*;/g; let m;
   while ((m=re.exec(h.slice(s,e)))) console.log(m[0]);
   "
   ```
   и просмотреть каждое совпадение — не должно остаться литеральных
   хексов, кроме сознательно нейтральных (белый/чёрный текст на кнопке
   с var()-акцентным фоном, если контраст рассчитан заранее).

4. **Хардкод в HTML (SVG `fill`, `stroke`, `stop-color`, JS-конфиги
   `data-tl-from/to`)** — десятки мест (`fill="#FFFF23"` на декоративных
   кружках-точках сбоку от таймлайна, `stop-color` в SVG-градиентах,
   `data-tl-from="{'color':'#ffff23', ...}"` у `.nav-logo`). Чинится
   одним блэнкет find-replace по HEX-строке сразу в `index.html` И
   `page.html` (файлы обязаны остаться идентичны):
   ```js
   const fs = require('fs');
   ['index.html','page.html'].forEach(f => {
     let h = fs.readFileSync(f, 'utf8');
     h = h.replace(/#ffff23/gi, '#NEWCOLOR');
     h = h.replace(/#fdf822/gi, '#NEWCOLOR');
     fs.writeFileSync(f, h);
   });
   ```
   После — проверить `grep -c "#ffff23\|#FDF822" index.html` (должно
   остаться 0, кроме упоминаний в комментариях, если есть).

**5. Растровые иконки — CSS их вообще не видит.** Три значка в карточках
"Мой путь" (`images/Frame 116046201-1.avif` — щит с галочкой,
`images/Frame 116046202-1.avif` — сертификат-звезда, и
`images/oleg-scales-badge.png` — весы "Правосудие") — это **готовые
PNG/AVIF с зашитым цветом**, не SVG с `fill`. Ни один текстовый
find-replace их не тронет. Перекрашивать — только через Pillow, по HSV
(Euclidean-дистанция до опорного цвета оставляет жёлтую кайму на
антиалиасинг-краях, HSV по hue/saturation её убирает):
```python
import colorsys
from PIL import Image
def recolor(path, new_hue_deg):
    im = Image.open(path).convert("RGBA"); px = im.load()
    for y in range(im.height):
        for x in range(im.width):
            r,g,b,a = px[x,y]
            if a == 0: continue
            h,s,v = colorsys.rgb_to_hsv(r/255,g/255,b/255)
            if s > 0.12:  # цветная фигура (а не нейтральный фон/тень)
                nr,ng,nb = colorsys.hsv_to_rgb(new_hue_deg/360, min(s*1.3,0.65), min(v*1.05,1.0))
                px[x,y] = (round(nr*255),round(ng*255),round(nb*255),a)
    im.save(path)
```
Та же логика — для `favicon.png`, `webclip.png`, `images/OpenGraph.jpg`
(эти три можно и просто перегенерировать скриптом с нуля, см. Часть III
Шаг 5 — они не фотографии, а сгенерированные композиции).

**Для технической кнопки-палитры** (живое сравнение вариантов, не
финальная перекраска) растровые значки решены иначе: заранее
сгенерирован по файлу-варианту на КАЖДУЮ палитру (`<имя>-dark1.avif`,
`<имя>-bork.png` и т.п., тем же HSV-скриптом выше, под hue акцента
той палитры), и сам `<img>` помечен `data-base-src="images/<имя>"`.
Объект `imageVariants` в JS переключателя мапит base-src → src для
каждой палитры; при клике переключатель просто подменяет `src`.
Добавляя новую палитру — сгенерировать вариант каждой картинки из
`imageVariants` под её акцент и дописать путь в объект (сам PNG/AVIF
редактировать не нужно, только сгенерировать новый файл рядом).

**Живой пример №1, "забытого места" (август 2026):** при первой перекраске
в синюю схему `.experience-number`/`.nav-experience-numb` и
`.hero-cta-button`/`.hero-button`/`.cta-button` были захардкожены на
конкретный синий хекс (`color: #7BBBFF` и т.п.) вместо `var(--yellow)`.
Сайт выглядел перекрашенным — но при следующей попытке сменить палитру
(на другой синий/тёмный вариант) эти элементы остались на СТАРОМ синем,
хотя всё остальное поехало. Нашли только когда переключили палитру и
сверили визуально. **Вывод: любой override в custom-блоке — всегда
`var(--yellow)`/`var(--black)`, никогда не литеральный хекс**, кроме
случая `.nav-logo` (см. пункт 2) и намеренно нейтральных цветов
(настоящий чёрный/белый текст, если он не должен зависеть от палитры).

**Тёмный фон — отдельная ловушка, и у неё уже есть решение: `--ink-fixed`.**
Если меняете не только акцент, но и делаете **фон тёмным** — весь текст,
который был `var(--black)` (тёмные "чернила" для светлого фона), должен
стать СВЕТЛЫМ, иначе тёмное на тёмном. Но `--black` в этом проекте
исторически отвечал за ДВЕ разные вещи:

1. цвет текста **на фоне body** — должен меняться вместе с палитрой
   (тёмный на светлом фоне, светлый на тёмном);
2. цвет текста **на элементах с фиксированным светлым фоном**, который
   палитра не трогает (плашки навигации `.nav-item-bg`, `.service-card`,
   `.about-card`, `.faq` — их фон захардкожен во внешнем Webflow CSS или
   в custom-блоке и никогда не красится) — такому тексту нужен ВСЕГДА
   тёмный цвет, иначе на тёмных палитрах он станет светлым на светлом и
   пропадёт.

Пока в проекте была только одна (светлая) палитра, роли 1 и 2 совпадали
и одной переменной хватало. Как только появились тёмные палитры —
роли разошлись, и понадобилась вторая переменная:

```css
body {
  --yellow: #7BBBFF;
  --black: #050F2A;    /* роль 1: текст на фоне body, меняется с палитрой */
  --ink-fixed: #050F2A; /* роль 2: текст на фиксированных светлых поверхностях,
                            ОДНО И ТО ЖЕ значение для всех палитр — никогда
                            не добавлять его в объект палитры в tweak-кнопке */
}
```

**Правило:** элемент лежит прямо на фоне body → `var(--black)`. У элемента
свой фиксированный (не зависящий от палитры) светлый фон → `var(--ink-fixed)`.
Если не уверены — посмотрите, красит ли что-то фон этого элемента при
переключении палитры (см. `<!-- TWEAK-PALETTE -->`): нет — `--ink-fixed`.

**Живой пример №2 (сентябрь 2026, пункты меню):** при добавлении тёмных
палитр текст пунктов меню (`.hero-navigation-link`) сначала оставили на
`var(--black)` — он корректно светлел на тёмном фоне body. Но у меню
есть плашка `.nav-item-bg` с фиксированным светлым фоном (см. выше) — на
ней тот же светлый текст стал НЕВИДИМЫМ (контраст ~1:1 вместо нужных
15:1). Похожая история — с иконками меню (`.nav-item-icon`): у них
вообще не было override-цвета, они просто наследовали `--black` от
body и точно так же пропадали на своей плашке. Обе правки — замена на
`var(--ink-fixed)`.

Но и это не всё: движок GhostEngine (см. 1.4) держит текст пункта меню
и его плашку в РАЗНЫХ местах, пока виден `hero` — текст «перелетает» в
верхнюю строку поверх фото (без своей плашки), а плашка с иконкой в это
время скрыты (`opacity:0`, раскрываются скролл-анимацией) в стороне.
То есть один и тот же текстовый элемент временно живёт СРАЗУ в двух
контекстах: без плашки (поверх фото hero) и на плашке (в шапке после
скролла) — а `var(--ink-fixed)` по определению делает его всегда тёмным,
что на тёмных палитрах ломает именно контекст «поверх фото».

Первая попытка — добавить светлый `text-shadow`-ореол вокруг тёмного
текста, чтобы тот же тёмный цвет читался в обоих контекстах. Технически
сработало, но выглядело как нежелательный "фон"/рамка вокруг текста —
не то, что нужно визуально. Заменено на явное переключение класса:
небольшой `ScrollTrigger` (см. блок `<!-- NAV-DOCKED TOGGLE -->` перед
TWEAK-PALETTE) ставит `.nav-docked` на `<body>` у ТОГО ЖЕ порога скролла
(29% top hero), что и scroll-reveal плашек, — CSS переключает цвет между
`var(--black)` (текст поверх hero, без плашки) и `var(--ink-fixed)`
(текст на плашке):
```css
.hero-navigation-link { color: var(--black); }
.nav-docked .hero-navigation-link { color: var(--ink-fixed); }
```
**Вывод:** если элемент бывает в ДВУХ визуальных контекстах с разными
фонами (а не только "на фиксированной поверхности" или только "на фоне
body") — одной переменной (и тем более псевдо-приёмом вроде тени) может
быть недостаточно; ищите на нём GhostEngine-пару (1.4) и `data-tl-*`
scroll-reveal атрибуты, и по возможности переключайте явным классом
через `ScrollTrigger`, привязанный к тому же порогу, что и сам reveal —
это чище и предсказуемее, чем визуальные трюки.

**Живой пример №3 (сентябрь 2026, ещё фиксированные поверхности):**
после примера №2 нашлись ещё элементы с точно тем же паттерном —
фиксированный светлый фон + унаследованный `var(--black)`: `.email-text`
(карточка email в сайдбаре, фон `.nav-email-wrap`), `.nav-top-text`
(описание в карточке "ЕВСИН®" в шапке hero, фон `.nav-top-bg`),
`.cta-text` (баббл "Готовы обсудить..." в CTA, фон `.cta-chat`),
`.capa-card-heading`/`.capa-card-text` (карточки "Преимущества", фон
`.capa-card-item`) — все получили `var(--ink-fixed)`. Возникли они не
одновременно, а по мере того, как ловили каждый в отдельном скриншоте —
если увидите НОВОЕ место с тем же почерком (текст читаемый на светлой
палитре, пропадающий на тёмной, элемент внутри чего-то со своим
хардкод-фоном) — не ищите новую причину, это тот же баг, тот же фикс.
Отдельный вариант того же бага — `.social-link` (кнопки "позвонить"/
"написать" в карточке "ЕВСИН®"): сам фон плашки фиксированный
(`#ebeada`), а вот ФОРМА иконки — не CSS-фон, а SVG-путь
`.social-bg-path` с `fill="currentColor"`, наследующий `var(--black)` —
тот же принцип, тот же `var(--ink-fixed)`, просто через `color`, а не
`background`. Глиф поверх (`.social-path-white`) — намеренно
константный `var(--white)`, не трогать.

Ещё нашлась гамбургер-иконка `.mobile-menu` (<768px) — та же
фиксированная светлая плашка (`#ebeada`), полоски иконки —
`fill="currentColor"` на `.mobile-menu-icon`, тот же паттерн, тот же
`var(--ink-fixed)`.

**Живой пример №4a (сентябрь 2026, `.nav-docked` не ставится на
мобильном):** пункты меню (`.hero-navigation-link`) на `<768px`
оказались НЕВИДИМЫ на своей плашке — тот самый баг из примера №2, но
уже вроде бы починенный. Причина: фикс из примера №2 переключает цвет
классом `.nav-docked` на `<body>`, который ставит `ScrollTrigger` — а
этот скрипт нарочно выключен на мобильном (`if (window.innerWidth <
768) return`), потому что там нет GhostEngine и, соответственно, нет
самого явления "текст на секунду висит без своей плашки" (см. 1.4 —
GhostEngine тоже выключен `<768px`). Но раз `.nav-docked` там никогда
не ставится, текст оставался на `var(--black)` (не-докнутое состояние)
навсегда — а плашка `.nav-item-bg` на мобильном есть ВСЕГДА (текст
рядом с ней с самого начала, лететь ему некуда). Правильное поведение
на мобильном — это ровно то, что `.nav-docked` даёт на десктопе,
только константно. Фикс — отдельный override внутри
`@media (width < 767px)` (в самом верху блока, до правил
opacity/visibility ниже):
```css
.hero-navigation-link { color: var(--ink-fixed); }
.hero-navigation-link.w--current { color: var(--ink-fixed) !important; }
```
**Вывод:** если правите что-то через доп. класс/скрипт, завязанный на
`window.innerWidth < 768` (GhostEngine, `.nav-docked`-триггер,
`ButtonHover` и т.п.) — не забудьте проверить, что происходит с тем же
элементом НИЖЕ этого порога: часто там нужен не "тот же фикс, что и на
десктопе", а его КОНСТАНТНАЯ версия (десктопный fix переключает
состояние по скроллу; на мобильном переключать нечего — там всегда
только один из двух контекстов).

**Живой пример №4 (сентябрь 2026, `.nav-logo` — цвет из JS, не CSS):**
бейдж "ЕВСИН®" в шапке красится не через CSS, а самим движком:
`data-tl-from`/`data-tl-to` на элементе несут JSON
(`{'color':'#7BBBFF','backgroundColor':'transparent'}` →
`{'color':'#000','backgroundColor':'#7BBBFF'}`), который `StyleEngine`
(см. 1.3) применяет через `gsap.fromTo` со scroll-scrub — переменных
CSS тут в принципе нет, только хардкод-хекс прямо в атрибуте (категория
4 выше). Обычная перекраска (find-replace по файлу) тут работает, но
ЖИВОЙ переключатель палитры так не может — атрибут читается СТРОГО
ОДИН РАЗ, при `StyleEngine.init()` на загрузке страницы; после этого
поменять JSON в атрибуте бесполезно, весь scroll-tween уже создан со
старыми значениями. Решение — точечный ре-запуск: в
`window.AnimationEngine` добавлен `rebuildStyleElement(el)` (убивает
`ScrollTrigger`, слушающий именно этот элемент, и вызывает
`StyleEngine.process(el)` заново). Свежесозданный scroll-tween не
подхватывает текущий прогресс скролла сам — нужен `refresh()`, чтобы он
сразу показал правильное (а не "from") состояние.

**Ловушка, в которую сразу же наступили:** первая версия звала
ГЛОБАЛЬНЫЙ `window.AnimationEngine.refresh()` (= `ScrollTrigger.refresh()`
для ВСЕХ триггеров на странице) после починки `.nav-logo` — и на живой
странице это на каждый клик палитры чуть сдвигало кнопки
`.nav-button`/`.nav-button-secondary` в hero (у них свой, отдельный
scroll-scrub FLIP-перелёт через GhostEngine, см. 1.4, `data-flip-start`/
`data-flip-end`), причём сдвиг НАКАПЛИВАЛСЯ с каждым переключением —
ровно так и заметили баг ("кнопки изначально нормально стоят, потом при
смене темы съезжают, а потом ещё больше"). Правильно — обновлять
прогресс ТОЛЬКО у своего нового триггера, а не у всех разом:
`rebuildStyleElement` теперь сам вызывает `st.refresh()` (метод
ИНСТАНСА `ScrollTrigger`, не статический) на только что созданном
триггере, а внешний код (переключатель палитры) вообще не трогает
`AnimationEngine.refresh()`. **Вывод: если на странице есть несколько
независимых scroll-scrub анимаций (GhostEngine, StyleEngine и т.п.) —
глобальный `ScrollTrigger.refresh()` пересчитывает ВСЕ их разом; чинясь
точечно, обновляйте прогресс ТОЛЬКО своего триггера через его
инстанс-метод `.refresh()`, а не через глобальный вызов.**

Если найдёте ЕЩЁ элемент с хардкод-цветом в `data-tl-from/to` — тот же
приём: подменить хекс в атрибуте + `rebuildStyleElement` (сам
обновит свой прогресс), НЕ трогать `AnimationEngine.destroy()+init()`
целиком (пересобирает вообще всё, включая FLIP-измерения GhostEngine —
риск визуального "скачка" непропорционален выгоде для точечной правки
одного элемента) и НЕ вызывать глобальный `AnimationEngine.refresh()`
(см. ловушку выше).

**Техническая кнопка-переключатель палитры** (временная, для сравнения
вариантов вживую — см. `<!-- TWEAK-PALETTE -->` в конце `<body>`) меняет
`--yellow`, `--black`, `background-color` и `color` инлайн-стилями на
`body` (инлайн побеждает любое правило в `<style>`). **`--ink-fixed` в
неё сознательно не входит** — он всегда `#050F2A`, одинаково для всех
палитр (см. выше); если однажды понадобится палитра со светлым текстом
даже на фиксированных поверхностях — придётся добавить это поле в каждый
объект палитры в JS И завести для него отдельную переменную, а не менять
значение `--ink-fixed` по умолчанию, чтобы не сломать остальные палитры.
Файл переключателя — единственное место, которое НЕ будет само
подхватывать новые override-селекторы: если добавляете новый
хардкод-хекс в custom-блок (категория 3 выше) — не забудьте, что
переключатель его не увидит, пока вы явно не заведёте такой же override
через `var()`.

**Правки ТОЛЬКО под одну конкретную палитру.** Не каждая правка обязана
быть универсальной через `var()` — иногда нужно поправить что-то именно
для ОДНОЙ палитры (пример: у "Семейный адвокат" в hero на Midnight Blue
не хватало контраста к фото, добавили обводку текста — но именно на
Bork и светлой палитре текст и так читался, обводка там не нужна и
только испортила бы вид). Переключатель ставит `data-palette="<ключ>"`
на `<body>` при каждом клике — таким правкам этого достаточно:
```css
body[data-palette="dark1"] .hero-heading {
  -webkit-text-stroke: 1px var(--ink-fixed);
}
```
Не пытайтесь и здесь изобретать универсальную формулу через `var()`,
если реальная проблема — у одной конкретной палитры.

## Часть III. Пошаговая сборка нового сайта

### Шаг 0. Подготовка

```bash
cp -r lawyer-site новый-клиент
```

Добавить запись в `.claude/launch.json` (свой порт) — сайты работают
параллельно, удобно сравнивать.

### Шаг 1. Собрать контент от клиента

Отправить анкету (`questionnaire.docx` — шаблон в этом проекте). Минимум:
имя, специализация, город, телефон/почта/мессенджеры, реквизиты, 4 вехи
карьеры, 6 услуг с пунктами, 6 кейсов, 3 отзыва, 6 FAQ, 2 цифры для
счётчиков, фото.

**Не выдумывать отзывы и кейсы.** Нет реальных — убрать блок целиком.

### Шаг 2. Текст: сквозная замена

Работать Node-скриптом с `.split().join()`, а не Edit — HTML в одну строку.

```bash
node -e "
const fs=require('fs');
const pairs=[['Старый текст','Новый текст']];
['index.html','page.html'].forEach(f=>{
  let h=fs.readFileSync(f,'utf8');
  pairs.forEach(([a,b],i)=>{
    const n=h.split(a).length-1;
    if(n!==1) console.log('WARN['+i+'] совпадений:', n);  // ← всегда проверять
    h=h.split(a).join(b);
  });
  fs.writeFileSync(f,h);
});"
```

**Всегда проверять число совпадений.** Один и тот же текст часто есть в
нескольких местах (см. 3.1).

### Шаг 3. Логотип (4 места!)

Буквы лого — **векторные контуры, не текст**. Обычная замена не сработает.

Места: `.nesh-logo-preload-svg` (прелоадер), `.nesh-logo-ghost` (гигантский
фоновый), `.nesh-logo-svg` (в панели), `#nesh-clip` в футере (`clipPath`).

Готовый рецепт — вытащить контуры из шрифта:

```bash
pip install fonttools brotli
python -c "
from fontTools.ttLib import TTFont
from fontTools.pens.svgPathPen import SVGPathPen
from fontTools.pens.boundsPen import BoundsPen
f = TTFont(r'fonts/ppneuemontreal-bold.woff2')   # кириллица есть
gs = f.getGlyphSet(); cmap = f.getBestCmap()
text = 'ФАМИЛИЯ'
x=0; parts=[]
for ch in text:
    g = gs[cmap[ord(ch)]]
    pen = SVGPathPen(gs); g.draw(pen)
    bp = BoundsPen(gs); g.draw(bp)
    parts.append({'d':pen.getCommands(),'adv':f['hmtx'][cmap[ord(ch)]][0],'x':x,'b':bp.bounds})
    x += parts[-1]['adv']
print('width:', x)
"
```

Затем сдвинуть каждый контур на его `x` и **отразить по Y**
(`y_new = cap_top - y`), потому что в шрифте ось Y направлена вверх, а в
SVG — вниз. Итоговый `viewBox="0 0 {width} {height}"`.

> **Шрифт `Tr 3 A` кириллицу НЕ содержит** — только `ppneuemontreal-*`.
> Проверять перед использованием.

Круглый аватар (фон вшивается в файл, как в оригинале):

## Часть IV. Каталог граблей

Всё ниже — реальные баги из сборки первого сайта. Каждый стоил времени.

### 4.1. Один текст в нескольких местах

«Получить консультацию» существовал в **4** экземплярах: `.hero-cta-button`
(призрак), `.nav-button` (шапка), `.nav-button` в мобильном меню,
`.cta-button` (нижний блок). Правка одного не меняла видимый.

**Правило:** перед заменой посчитать вхождения; после — проверить, что
изменилось именно видимое (через `getComputedStyle`/`getBoundingClientRect`,
а не на глаз).

### 4.2. `!important` ломает анимацию молча

Симптом: кнопки раздваиваются, появляются сразу на загрузке, съезжает
мобильная вёрстка. Причина: `width:auto !important` на `.nav-button`
запрещал GSAP менять ширину.

Отдельно: `.hero-buttons-wrap{display:flex !important}` без медиа-запроса
ломал мобильную раскладку (там по замыслу `display:none`).

**Правило:** нет `!important` на геометрию элементов движка. Если текст не
влезает — сначала проверить `el.scrollWidth > el.clientWidth`, часто
переполнения нет вовсе; если есть — **сокращать текст**, а не ломать CSS.

### 4.3. Рассинхрон пары ghost↔real

`.experience-number` заменили на `<p>30</p>`, парный `.nav-experience-numb`
остался `<svg>` с «7+». Тип `icon_center` считает масштаб по отношению
размеров — цифра растянулась в «Ъ0».

**Правило:** правки только парами, тип тега не менять.

### 4.4. `<span>` внутри `.hero-heading`

Заголовок режется `SplitText` на строки. Вставленный
`<span style="display:inline-block">` ломал разбиение.

**Правило:** внутри `.hero-heading` только текст и `<br>`.

### 4.5. Перенос строки внутри якоря (`data-connect`)

У якорей вида `<span>&nbsp; &nbsp; &nbsp;</span>` между `&nbsp;` стояли
**обычные пробелы**. По ним браузер переносил строку, якорь разрывался на
две строки, его прямоугольник раздувался (992×188 вместо 140×100) —
и карточка улетала в случайное место.

**Правило:** всем якорям `data-connect` ставить `style="white-space:nowrap"`.
Эта же уязвимость есть в оригинале heynesh.com — просто там не проявилась.

### 4.6. Правка текста двигает все карточки следом

Попытка «раскидать» иконки добавлением `&nbsp;` между словами сдвинула
переносы по всему абзацу: было 2 конфликта, стало 11.

**Правило:** для сдвига карточки использовать `data-offset`, а не правку
текста. Если нужно больше строк — удлинять текст осмысленными словами,
проверяя после каждого шага.

### 4.7. Ловушка порядка правил в исходном CSS

```css
@media (max-width:479px){ .hero-buttons-wrap{display:flex} }  /* раньше в файле */
@media (max-width:767px){ .hero-buttons-wrap{display:none} }  /* позже в файле */
```

При ≤479px истинны **оба** условия, побеждает **последнее в файле**, а не
более узкое. Это намеренное поведение шаблона, не баг.

### 4.8. Lenis перехватывает колесо мыши

Карусель отзывов не листалась трекпадом. Плавный скролл страницы (Lenis)
забирал события `wheel` себе.

**Решение:** `data-lenis-prevent` на контейнер `.swiper` + модуль
`mousewheel` в конфиге Swiper с **`forceToAxis: false`** (при `true`
горизонтальная карусель требует именно горизонтального жеста и обычная
вертикальная прокрутка не работает).

### 4.9. Чужой контент, который легко забыть

- **ImageTrail** в футер-логотипе подтягивал фото портфолио Ненада с
  внешнего CDN при наведении. Отключено удалением цели
  `<g id="image-trail-group">` — модуль не находит селектор и тихо не
  стартует.
- **`.client-img` в отзывах** — до сих пор фото реальных клиентов Ненада
  (`Danette Beal.avif`, `Klemen Vute.avif`, `petar_s.jpeg`). **Заменить
  обязательно.**
- **`.work-image`** — скриншоты чужих проектов (`Frame *.avif`).
- Атрибуты `data-wf-domain="heynesh.com"`, `data-wf-page`, `data-wf-site` —
  безобидные следы экспорта, но лучше почистить.

### 4.10. Двойная инициализация движка

Повторный `AnimationEngine.init()` без перезагрузки дублирует ScrollTrigger-пины
и ломает высоту документа (`Animation engine already initialized` в консоли).

**Правило:** после правок — полная перезагрузка страницы, `init()` максимум
один раз.

### 4.11. Особенности среды разработки

- Вкладка инструмента может считаться скрытой (`document.hidden`), тогда
  `requestAnimationFrame` не идёт и анимации не стартуют сами → вызвать
  `window.AnimationEngine.init()` вручную.
- Скриншот иногда возвращает пустой/устаревший кадр. **Доверять
  `getBoundingClientRect`/`getComputedStyle`, а не картинке.**
- `loading="lazy"` в этой среде может не срабатывать — картинка «не
  загружена», хотя файл валиден.

## Часть V. Как добавлять новые блоки

### 5.1. Дублирование карточки

Самый надёжный способ — скопировать существующую и заменить содержимое.
Границы блока определять **подсчётом вложенности**, а не регуляркой:

```javascript
function extractBlock(html, marker){          // marker: 'class="service-card"'
  const i = html.indexOf(marker);
  const start = html.lastIndexOf('<div', i);
  let depth = 1, p = html.indexOf('>', start) + 1;
  while (depth > 0) {
    const o = html.indexOf('<div', p), c = html.indexOf('</div>', p);
    if (c < o || o === -1) { depth--; p = c + 6; }
    else { depth++; p = html.indexOf('>', o) + 1; }
  }
  return { start, end: p, html: html.slice(start, p) };
}
```

После вставки — **обязательно** проверить баланс `<div>`. В прошлый раз
регулярка добавила по лишнему `</div>` в 6 карточек; ловится скриптом,
который считает глубину и сообщает, где она ушла в минус.

### 5.2. Что поправить в копии

- **Уникальные `id`** — Webflow генерирует `w-node-...`, `w-dropdown-N`.
  Для FAQ важны связки `id="w-dropdown-toggle-N"` ↔
  `aria-controls="w-dropdown-list-N"`.
- **`data-tl-start`/`data-tl-end`** — задают, когда блок появляется при
  скролле. У соседних карточек значения разные (`-45%`, `-4%`, `20%`,
  `58%`) — при копировании выставить своё, иначе анимация синхронная.
- **`data-connect`** — для карточек-привязок нужен новый id и **новый
  якорь** в тексте (и в мобильном тексте тоже).

### 5.3. Смена числа карточек в сетке

`.service-wrap` изначально `display:flex` в один ряд с фиксированной
шириной карточек `22.22vw` — 6 карточек не помещались. Переведено в grid:

```css
@media (min-width: 768px) {
  .service-wrap { display: grid; grid-template-columns: repeat(3, 1fr); }
  .service-card { width: 100%; }
}
```

Для выравнивания разновысоких блоков внутри карточки:
`.service-card{height:100%}` + `.service-bottom-content{margin-top:auto}`
(+ `min-height` тексту, если нужно ровнять и верх).

### 5.4. Целая новая секция

1. Скопировать `<section>` с похожей структурой.
2. Дать новый `id`, обновить `data-tl-trigger` внутри на него.
3. Добавить пункт меню — **два элемента**: `.hero-navigation-link`
   (в `.nav-menu-item`) и парный `.hero-link-ghost` с тем же `data-link-id`.
4. Проверить порядок секций в DOM (влияет на скролл-триггеры).
